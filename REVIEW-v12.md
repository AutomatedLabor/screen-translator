# Fresh-eyes review — Screen Translator v1.1.0 (Kotlin / Compose / AccessibilityService)

**Scope:** `app/src/main/java/com/translator/screen/**/*.kt`, `app/src/main/AndroidManifest.xml`, `app/src/debug/AndroidManifest.xml`, `app/src/main/res/xml/accessibility_service_config.xml`, `app/src/main/res/values/{themes,colors,strings}.xml`, `app/src/main/res/drawable/*.xml`, `app/src/main/res/mipmap-anydpi-v26/*.xml`.

**Out of scope (already covered by the prior Council review — COUNCIL-REVIEW.md):** `build.gradle.kts`, `.github/workflows/build.yml`, signing config, CI fail-closed, cert SHA-256 baseline, concurrency-via-singleton-instance, v-scheme disposition, keystore in RUNNER_TEMP, wrapper-validation, property-gated signingConfig. Council findings #9 (themes parent / windowLightStatusBar / edge-to-edge general), #10 (enabled-services split), #14 (close-button touch slop), #15 (typeWindowContentChanged), #16 (GlobalScope warmup), #19 (empty App stub), #21 (displayMetrics vs currentWindowMetrics) are noted but NOT repeated here; this review layers on top of them and finds issues the Council did not call out.

**Method:** Read every Kotlin file under `app/src/main/java/com/translator/screen/`, both manifests, every XML resource, and the instrumented-test activity. Searched for NPE risks, lifecycle leaks, threading hazards, edge-to-edge enforcement (targetSdk 35), overlay cutout / race issues, deprecated API usage, unused resources, and a11y/UX defects. Findings grounded in file:line evidence.

**Honesty disclosure:** Single-reviewer pass (no simulated personas). Findings are concrete and reproducible from the source. Severity is the reviewer's judgment; P0 = core-feature-broken or crash, P1 = worth fixing this cycle, P2 = backlog.

## Verdict

The codebase is well-structured and defensively written in most places — the `SupervisorJob` scope, the `BadTokenException` handling, the `closed` AtomicBoolean, the LruCache test coverage, and the depth/node bounds in the extractor all show real care. But there is one P0 that gates the core feature (#1, the shade-open race that silently no-ops the translation from its only entry point), a cluster of P1 leaks and a11y defects that compound on each other (#2 view leak, #6 missing contentDescription, #8 translator native leak, #9 CancellationException swallowing, #11 sp-vs-dp a11y), a build-config mismatch that ships a dangling exported activity in the debug APK (#3), and a targetSdk-35 edge-to-edge gap that will visibly regress on Android 15 (#4). None of these are hard to fix — most are 5-15 line changes — and together they move the app from "works on the developer's device" to "works on the long tail of devices and assistive-tech configurations." Recommend fixing #1, #2, #3, #6, #8, #9, #11, #12 before the next release tag; the remaining P1s and all P2s are reasonable to batch into a follow-up.
